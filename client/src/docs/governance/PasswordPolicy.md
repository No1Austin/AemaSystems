# AEMA Systems

# Password Policy

Version: 1.0

Effective Date: July 5, 2026

Owner: AEMA Systems

Review Frequency: Every 12 Months

---

# 1. Purpose

The purpose of this Password Policy is to establish minimum password and authentication requirements for protecting AEMA Systems, its software platforms, customer information, and business operations.

Strong authentication is a fundamental part of AEMA Systems' security program.

---

# 2. Scope

This policy applies to:

• AEMA Systems

• AEMA AI

• TaskFlow

• AEMA Invest

• Internal systems

• Administrative accounts

• Cloud services

• Contractors

• Future employees

---

# 3. General Requirements

Passwords must be:

• Unique

• Difficult to guess

• Kept confidential

• Never shared with unauthorized persons

Passwords must not be reused across important business systems.

---

# 4. Password Standards

Passwords should contain:

• At least 12 characters

• Uppercase letters

• Lowercase letters

• Numbers

• Special characters where supported

Long passphrases are encouraged.

Example:

CorrectHorseBatteryStaple2026!

---

# 5. Multi-Factor Authentication

Where available, Multi-Factor Authentication (MFA) should be enabled for:

• Email

• GitHub

• Stripe

• Supabase

• Vercel

• Render

• Cloudflare

• Banking

• Password Manager

Administrative accounts should always use MFA where supported.

---

# 6. Password Managers

AEMA Systems encourages the use of reputable password managers.

Passwords should not be stored in:

• Plain text documents

• Sticky notes

• Emails

• Chat messages

---

# 7. Shared Credentials

Shared accounts should be avoided.

Where shared credentials are unavoidable, access should be:

• Limited

• Documented

• Reviewed regularly

Shared credentials should be changed immediately when access is no longer required.

---

# 8. Compromised Passwords

If a password is suspected to be compromised:

• Change it immediately.

• Review recent account activity.

• Enable MFA if not already enabled.

• Notify the business owner if customer or company information may have been affected.

---

# 9. Administrative Accounts

Administrative accounts require additional protection.

These accounts should:

• Use unique passwords.

• Enable MFA.

• Be used only when administrative privileges are required.

• Not be used for everyday browsing or personal activities.

---

# 10. Third-Party Services

Passwords protecting services such as:

Stripe

Supabase

Render

Vercel

GitHub

Cloudflare

Resend

should receive the highest level of protection because they secure core business operations.

---

# 11. Compliance

Failure to follow this policy may increase the risk of unauthorized access, data breaches, fraud, and service disruption.

AEMA Systems expects all persons with access to company systems to follow this policy.

---

# 12. Review

This policy will be reviewed at least annually or whenever significant changes occur to AEMA Systems' technology or operations.
